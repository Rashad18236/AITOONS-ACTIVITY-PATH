# Activity Path Poster

A sister product to the Flight Path Poster for runners, cyclists, hikers and triathletes. The customer sends the recorded file of one activity (a race, a big ride, a mountain hike, a triathlon) with the order; the shop owner runs it through this local tool, which turns it into the same physical poster as the flight product, as ready-to-print OrcaSlicer projects:
`frame.3mf` (black backplate + ring, white text as its own body), `relief.3mf` (multi-body
green terrain / blue water (lakes, rivers, sea) / grey high-alpine band, runways and main roads (same slot 3), one AMS slot per colour) and the path (a raised wall crossing the relief along the route, standing in a constant-floor slot). On the flight poster the wall's height is the altitude; an athlete is always on the ground, so here the wall **stands on the terrain and its height above the ground is their heart rate**: the hard parts of the race stand tall, the easy kilometres stay low, and a climb reads twice. Every print setting is embedded: open, slice, print. Customers never see or touch the tool.

## Rules

- Printed in PLA on a Bambu Lab A1 with a 0.4 nozzle (the only printer the projects target), 256×256mm plate, poster is one piece
- Three sizes only, `poster.SIZES_MM` = (216, 170, 120), 216 the default
- Footprints are checked against `USABLE_MM` (226), never the bare 256 plate
- Design decisions with Fable, implementation via Opus subagents
- Ponytail full mode during coding: laziest working solution, heightmap ops over 3D booleans, no speculative features
- Local only (localhost), single user, no auth, no persistence of user data; OSM responses are cached in process only

## Run

```bash
uv run uvicorn app:app --reload
# open http://localhost:8000
uv run python check_output.py frame.3mf relief.3mf path*.3mf --params '{"size_mm":170}'   # every path file
```

## Architecture

- `app.py` — FastAPI, serves `static/`. `/generate` takes `files` (several), `params` JSON, `workout_date`/`workout_time` (Health only) and returns `{frame, relief, paths: {stem: b64}, resolved, legs}`, `legs` being `legs_note`. Size whitelist, then `read_activity` on each upload's `f.file` (never `await f.read()`: a Health export can be GB); every upload is closed in a `finally`. Any `ValueError` is a 400 with its message: from the params (a `TypeError` from `Params(**kw)`/`resolve` too, e.g. `"wall_mm": "abc"`), from reading the order (`read_activity`) or from building the poster, which covers `build_poster`'s input checks (size, chin, slot, no GPS leg) and, by design, an internal bug that happens to raise `ValueError` too (the `ponytail:` in `/generate`). Network failures (Overpass, tiles) and any other exception from building are a 502. A wall in `group_walls` that produced no path file (every piece under `MIN_PIECE_MM`) adds `"<sport, or activity for strip>: too short to print at this size, no path file"` to `legs`, found by comparing the wall names with the returned bodies' names
- `activity.py` — customer files → `Leg`s (sport family, lat/lon, POSIX time, heart rate with NaN where the file has none). GPX and TCX readers on stdlib XML, matched on local tag names because exporters differ in namespace prefixes; a GPX without timestamps is refused as a planned route; a naive time is UTC. FIT through `garmin-fit-sdk` (the one added dependency; anything it cannot decode is a `ValueError` naming the file): each session becomes a leg, a session without positioned records an empty one, and a `transition` session's records join the following leg so the path stays continuous. `sport_family` maps any exporter's sport name to swim/bike/run/transition; `smooth_hr` is the centred `HR_WINDOW_S` (30s) mean of the finite samples, O(n). `parse_health_zip` reads an Apple Health `export.zip` in place, never extracted: one `iterparse` pass over the largest non-`cda` `.xml` member, `root.clear()` after each top-level element so a multi-GB export stays flat in memory, read through `_NoDTD`, which cuts the internal DTD subset at the stream's head (`<!DOCTYPE` up to its `]>`, the rest passed through as read) because iOS 16 wrote exports whose subset expat rejects — pinned by a fixture with a malformed `ATTLIST`, not by a real export, keeping only the date's workouts with a route and the heart-rate records within a day of it. The workout is picked by date and optional start time (within 30 min, an exact minute breaking a tie) and never guessed: none, or several, is a `ValueError` listing "HH:MM Type"; an Apple Watch triathlon (`SwimBikeRun`) is refused in favour of Strava/HealthFit files. Its route GPX goes through `parse_gpx` and takes HR interpolated by time, NaN where the nearest record is over `HR_GAP_S` (15s) away; a damaged zip or XML is a `ValueError` too. **`read_activity(files, workout_date, workout_time)` is the order's entry point** (`/generate` turns its `ValueError` into a 400). It dispatches on the lower-cased extension: `.gpx`/`.tcx`/`.fit` are read whole, a `.zip` is handed to `parse_health_zip` as the file object and never read whole, anything else is refused. The trust boundary is the customer's file, so whatever a parser raises reaches the caller as a `ValueError` naming the file: one that already starts with its (non-empty) name passes unchanged, anything else (a non-XML `.gpx`, a `float("north")`) becomes `"{name}: could not read this file (Type: msg)"`, never a 500. Each leg is then cleaned: non-finite fixes dropped, sorted by time, consecutive repeated positions dropped, then GPS spikes — an interior fix whose speed both in and out exceeds `MAX_SPEED_MS` (60 m/s), then an end too fast to its new neighbour (equirectangular distance, dt floored at 1s; isolated spikes only, two bad fixes in a row survive). An order with no leg of 2+ fixes is refused ("no GPS track… indoor or pool activity?"). Legs sort by first timestamp, an empty one staying after the leg it followed in the files. Sports come from the legs with 2+ fixes: all blank and exactly three → swim, bike, run in time order; all blank otherwise → single sport; some blank → refused naming those files; more than one sport with one outside swim/bike/run → refused naming it. `group_walls` gives `[("strip", legs)]` for one sport (or none) and otherwise one `(sport, legs)` per sport in order of first appearance — same-sport legs merge into one wall — leaving out legs under 2 fixes. `legs_note` is the status line, `" · "`-joined: the Health workout's source first when there is one, then per leg (label the sport or "activity") "no GPS track, not printed", "no HR, low line" at 0% finite HR, or "HR n%" — coverage only, never an HR value or a coordinate. No geometry beyond the spike filter's speed, never imports `poster`
- `poster.py` — core: `build_poster(legs, p)` → `resolve` and the input checks → `group_walls` → `legs_bounds` (one map for the whole order) → fetch DEM (AWS Terrain Tiles, terrarium, no key) + OSM water, coastline, runway and road geometry (one Overpass call, `_overpass` lru-cached per query, mirrors tried until one answers *without* a `remark`) → walls: per sport `collapse_passes` over its legs' `leg_stations`, then `assign_lanes` (lane pitch and tolerance both `r`), `wall_masks`, with `r = lane_mm / res_mm` and `ramp = ceil(2r)` from `_wall_dims` → compose 2D heightmaps (frame + text mask, green/water/snow relief, the slot = `groove_from_masks`) → `wall_tops` on that surface → mesh to `frame.3mf` + `relief.3mf` + the path files (OrcaSlicer projects, `write_3mf`). **One path file per wall, one filament each:** `path.3mf` with a red `strip` body for a single sport (or none), else `path_swim.3mf` / `path_bike.3mf` / `path_run.3mf`, body named after the sport, `COLORS` white `#FFFFFF` / red `#CC2222` / yellow `#F4EE2A` (the water is blue, so the swim never is). `SLOTS` and `PLATES` carry `path_<sport>` keys (the same settings as `path`), and `write_3mf` picks the plate from the first body's name. A wall whose every piece was dropped has no file (and `/generate` says so in `legs`). `check_output.py` fails a path file holding more than one body (one filament per path plate, spec 4) or, when the file is named `path.3mf` / `path_<sport>.3mf`, a body not named `strip` / `<sport>`
- `orca_profile.py` → `orca_a1_pla.json` — the A1 0.4 / 0.24 Draft / Bambu PLA Basic system profiles, inherits chains flattened, vendored (committed). Regenerate with `uv run python orca_profile.py` against the installed Orca after an Orca update
- `static/index.html` — the form posts `files` (several: `.gpx`/`.tcx`/`.fit`/`.zip`), `params` (the numeric fields, `wall_mm` among them, blank = auto) and `workout_date`/`workout_time` (native date/time inputs, Health only); the three.js preview places frame, relief and every `paths` entry at the relief offset, each wall in its `COLORS` colour; one download link per output file, the path links built per stem; the status line is `legs` plus which file goes on which AMS slots
- `test_poster.py` — self-check on synthetic `_leg`s (`LEGS3` one run, `TRI3` a triathlon) and a horizontal `_band` groove for `compose_parts`: walls, groove fit, relief, caption, 3MF, `/generate` with GPX/FIT/Health uploads, `check_output.py` on every path file, and the real Orca CLI on every plate of the triathlon
- `test_activity.py` — the readers and the order rules (`read_activity`, `group_walls`, `legs_note`; `_file` wraps bytes as an upload), against files built in memory by `_pts`/`_gpx`/`_tcx`/`_fit`/`_health_zip` (the last an iPhone-layout export with a `pad_cda`-byte stored `export_cda.xml`; reused by the later reader and order tests)

**Every output is a finished OrcaSlicer 2.3.2 project, A1 0.4 only.** Orca fills a loaded project's config from compiled defaults and applies it as "(modified)" edits over the preset `print_settings_id` names, so a partial `project_settings.config` would blank `machine_start_gcode` and every key it left out. `write_3mf` therefore embeds the whole vendored chain from `orca_a1_pla.json` (filament lists tiled per slot, machine/process lists left at length 1) and puts `COMMON`, `PLATES[plate]` and the per-part `PART_OVERRIDES` (the caption: 2 walls at 0.40 with only-one-wall-top ON, so its top layer is an outline plus a top surface; bead-only tops read as hollow outline letters in Orca) on top. Those tables in `poster.py` are the truth and `docs/print-settings.md` is the rationale. Speeds are the user's standard: every print speed `SLOWER_MM_S` (50) under the Draft preset, top surfaces at 50 mm/s. `different_settings_to_system` (`[print, filament 1..n, printer]`, `;`-joined keys) lists every override that differs from the named system presets: the CLI slices the full config regardless, but the **GUI** keeps only the listed keys as "(modified)" — without it, the user changed one speed, saved, and got the bare 0.24mm Draft preset back (classic walls, 35mm tower, 15% crosshatch). The filament slots are fixed per plate (`SLOTS`): relief.3mf always declares three filaments, even when a dry poster uses only slot 1, so the AMS mapping never shifts. Placement is on the build item only, never in the vertices (`check_output.py` and `read_3mf` measure the local frame): x centred on the 256 bed, y centred in the space behind the prime tower (`138 - h/2`, i.e. the 216 two-line frame sits at y 25–251, brim 20–256), and z dropped onto the bed (a wall's own floor is 1.16). The tower is 130mm wide at x 63 / y 5, its brim 0–16. Sliced at 0.24 on the 216 order it is 6.75mm deep on the frame. That is Orca's height-based stability minimum: at 0.12 a 180mm tower sliced the same depth. With brim and cone it reaches y 16.8, 3.6mm short of the frame's brim; on the relief it reaches 17.3, against a brim at 36. `USABLE_MM` is unchanged. `test_orca_slices_every_plate` runs the real Orca CLI headless when it is installed.

Key invariant: every body comes off the same heightmap, so they always fit. The relief plate glues into the frame ring (fit clearance ceil-rounded up to a whole pixel, ≥0.2mm per side — rounding down gives an interference fit); each wall glues into the slot with 0.30mm per side. The slot is carved to a constant `SLOT_FLOOR_MM = 1.16` floor (depth varies with terrain, the floor does not), and each wall runs from that floor up to the terrain under it plus `wall_height` (at least `proud_mm`).

**Caps follow the slot.** Water and road caps are not kept off the groove: inside it `cap_top` drops to `SLOT_FLOOR_MM` and `cap_bot` to `SLOT_FLOOR_MM - SLOT_CAP_MM`, so the slot's walls and floor are blue over water and grey on a road. Kept off (and meshed per four-corner cell), 0.3mm of clearance plus up to 0.4mm of full-height green rim showed on each side of the strip along the whole path, even over the sea. The wall still seats on the flat `SLOT_FLOOR_MM`, now on the cap's top. `SLOT_CAP_MM` is 0.48 (2 layers), not `cap_mm`, because 1.16 − 0.96 would leave only the 0.2mm first layer green; the green under it sits at 0.68 = 0.2 + 2×0.24, on the grid. (That is also why the floor is 1.16 and not 0.92, the boundary nearer the old 1.0: 0.92 − 0.48 leaves 0.44mm.) Green is carved only under cells the mesher really meshes, so a 4px road leaves no orphan pits along its edge.

The DEM is blurred once (`smooth_px` = 1px) and the terrain surface is snapped to a printable layer boundary before caps and slot are cut, so flat ground slices as uniform layers. The grid is `FIRST_LAYER_MM + n*layer_mm` (0.2 + n*0.24), *not* `n*layer_mm` — the printer's first layer is thicker than the rest. The layer is 0.24 since the flight tool's 216 order was measured with the Orca 2.3.2 CLI. At 0.12 the relief took 18.84h with 155 filament changes (one per layer, because the roads drape into the slot) and the frame 8.29h (ironing alone ~60%). At 0.24, with frame ironing off and 7% infill and relief walls 2 / top 3 / 10%, the measured times are frame 2.69h and relief 9.55h with 77 changes (`docs/print-settings.md` head has the variants). The terrain step is 7.6m instead of 3.8m, which the user accepted. One helper, `_snap(z, p)`, does it for the terrain, the wall tops and the `z_snow` plane. Every fixed z is a layer boundary or a whole layer count, pinned by `test_fixed_constants_sit_on_the_default_layer_grid`: `SLOT_FLOOR_MM` 1.16, water `cap_mm` 0.96, text 1.20, `base_mm` 4.04, `plate_mm` 2.12, `frame_height_mm` 10.08 at 250mm (9.96 rounded up), `proud_mm` 0.96 at 250mm. The *scaled* thicknesses are not whole layer counts by luck, so `resolve()` snaps them: `_layers(v, p)` is `_snap`'s delta form and rounds `frame_height_mm`, `proud_mm` and `relief_mm` (the last through `exaggeration`, which is what reaches the relief ceiling) **up** to whole layers — up, because each has a printability floor that rounding down can cross. Without it a 170mm poster put the ring top at 10.81mm, 0.05mm above boundary 88 of the old 0.12 grid, and the slicer's rounding — not the geometry — decided which layer the black/white colour boundary landed on. `frame_mm`, `text_mm`, `groove_w_mm` and `chin_mm` are in-plane and are deliberately never snapped.

**The vertical scale is the terrain, floored at 300m** (spec 6.4). `to_mm` maps `span = max(e1 - e0, SPAN_FLOOR_M)` metres onto `relief_mm * exaggeration`, `SPAN_FLOOR_M = 300`, the old flight span's lower clip. Terrain range alone stretched Blackpool's 30m of coast over the whole relief (0.86mm/m) and flat land read as hills; floored, 30m of city is a tenth of the relief. In the mountains the terrain range wins and an alpine trail run looks as it would on a flight poster. The heart-rate wall has its own mm scale and does not touch this one, so the wall ceiling `check_output.py` measures against is `plate_mm + relief_mm*exaggeration + proud_mm + wall_mm`.

**The sea is a coastline, not a polygon.** OSM has no sea polygons, only `natural=coastline` ways with land on their left. `_sea_mask` draws them as 1px 8-connected lines, labels the pieces with 4-connected floodfills and lets every segment vote +1 for the piece on its right, −1 for its left — votes, because a pier doubles back within a pixel and a single seed lands across it (99.8% of Blackpool flooded vs 48.5% by vote). Not the DEM sign: a polder is below zero and still land. `build_poster` sets the DEM to 0 under the sea *before* the one blur (terrarium carries bathymetry, −7.85m off Blackpool), so the shore blends with 0 and the sea prints as the usual flat conformal water cap. Closed coastline ways are islands and never reach the polygon rasteriser, which would paint them as lakes.

**Overpass answers 200 with partial data.** A query that hits `[timeout:120]` or `[maxsize:]` does not fail: it returns HTTP 200, the elements gathered so far, and a `remark` ("runtime error: Query timed out…"). The union is evaluated in order, so roads vanish first and the coastline next — and a missing coastline leaves the seabed bathymetry in the DEM. That showed up as a different street grid and "different relief" between two regenerations of one order, with mirror load flipping by the minute. `_overpass` therefore rejects any response carrying a `remark` (or no `elements`), tries the four `OVERPASS_URLS` in order, 150s each, one try per mirror (`_get(..., tries=1)`; tiles keep their retry), caches complete responses in memory per query string for the server's life (a raise is not cached, so a failure retries next call), and raises `RuntimeError` when all four fail. `build_poster` no longer soft-fails it: `/generate` is a 502 whose message reaches the status line, never a poster without its water. The >4° transoceanic guard still returns empty masks without asking.

**Grey is also runways and main roads, picked by zoom.** `fetch_osm_masks` works out the poster's ground scale in m per printed mm and asks Overpass only for the `ROAD_TIERS` classes whose limit it is under (tertiary ≤60, secondary ≤150, primary ≤400, trunk ≤1200, motorway ≤3000 m/mm): Blackpool at 36.7 m/mm gets tertiary and up, ≈8.5% of the plate plus 0.3% runway; residential would add another 15% and read as a grey block. Roads are drawn `ROAD_MM` = 1.2mm wide (3 extrusions, clear of the 0.84 colour floor); a runway at its OSM `width` (or `RUNWAY_M` = 45m) on the poster's scale, floored at `ROAD_MM`, and an `area=yes` runway as a polygon. If the drawn grey still exceeds `ROAD_MAX_FRAC` (15%) the finest class is dropped and it says so. Tunnels are skipped; no taxiways, aprons or `_link` roads. Roads print as the same draped cap as water, in the grey band's colour and slot 3 (no new spool); `lc` sets them after water, so a bridge is grey across the river, and never over snow.

**Grey is an elevation band, not a cap.** The terrain solid is split at the horizontal plane `z_snow` (= `snow_line_m` on the relief's own mm scale, snapped): green below, a grey solid from that flat plane up to the surface above. A conformal 0.6mm grey cap surfaced as a 0.26mm stripe on median alpine slope — under one extrusion width, which the slicer merges into the neighbouring colour ("blotted grey"). The two bodies meet exactly at `z_snow` and their union is still the same surface heightmap, so this changes colour volume, not shape. The footprint is the bare `elev >= snow_line_m` threshold intersected with `surface > z_snow` — no morphology: an opening dropped small peaks from grey while leaving them in green, so green towered above the plane and the two colours shared layers. A small peak is a solid band volume that prints fine, and cell-based meshing already drops sub-2-cell blobs. Water stays a conformal `cap_mm` cap — lakes are flat.

**The caption bar is a chin, and the text has its own grid.** `size_mm` is the poster's **width** and the square relief area; `chin_mm` is extra frame hung *below* it, so the frame grid is `(N + chin_px, N)` while `N`, `M` and `fpx` keep their formulas — the ring opening and the relief are unchanged by construction (byte-identical, and pinned by a test). A poster therefore measures `size_mm` × `size_mm + chin_mm`, and **both** must fit the 256 plate; `check_output.py`'s footprint rule is per axis for that reason. `chin_mm` is auto: it is whatever `text`/`text2` need beyond the ring's own bottom bar, `block + 2*TEXT_MARGIN_MM - gridded_ring` rounded up to a pixel, so no caption means no chin and every earlier poster is unchanged. `gridded_ring` is `(int(frame_mm/res_mm) - 1) * res_mm` — the bar *as the mesher lays it out*, since frame rows `N-fpx..H-1` span one pixel less than the nominal `frame_mm + chin_mm`. Line 2 is a subtitle at `SUB_RATIO` (0.65) of line 1 with `GAP_RATIO` (0.35) between them. Note the auto chin fires for **any** caption: a single-line poster at 250mm is 2.4mm taller than the bare square (252.4 vs 250), and a two-line one 10.4mm taller — which puts 250mm two-line **over** the 256 plate. That is why the largest offered size is **216**: `SIZES_MM = (216, 170, 120)` is the shop's list, and every entry has to (a) fit **`USABLE_MM`** with *every* caption it can be ordered with (216 two-line = 215.6 × 226.0mm, landing exactly on it) and (b) be a whole number of `res_mm` pixels. (b) is why it is not 245 or 218: `_grid` truncates `N = int(size_mm/res_mm)`, so 245mm is 612.5px and prints **244.4mm** — 0.6mm under nominal, which `check_output.py`'s ±0.5 footprint rule fails. On the grid the width is short by exactly one pixel, which that rule allows.

**A mesh that fits the plate does not fit the print.** `PLATE_MM` (256) is the physical bed and is *not* the ceiling anything is checked against. `USABLE_MM` = `PLATE_MM - 2*BRIM_MM - TOWER_GAP_MM - TOWER_MM` = **226** is, on both axes, and it is what the `build_poster` guard, `max_size_mm`, `check_output.py` rule 3 and `/dimensions`'s `fits` all use. Shipped once without it: a 240mm poster meshes 239.6 × 250.4mm, passes a 256 rule, and Studio refuses it — the 5mm brim `docs/print-settings.md` makes mandatory on a plate this size puts it 4.4mm off the bed on its own, and the 130 × 6mm prime tower still has to go somewhere. The tower is not optional for `relief.3mf`: its bodies overlap in z (the flight tool's 216 D-EMFE order: terrain 0–18.44, water 0.68–3.80, roads 0.68–16.04), so most layers carry two colours. `frame.3mf` is the exception — frame 0–12.68, text 12.68–13.88, no overlap, so it is a *single* filament change and could be printed without a tower; the budget deliberately does not exploit that, since one number that holds for every plate beats two that need remembering. Both axes get the tower allowance because the tower is a fixed-orientation rectangle: assuming it can be rotated into a side strip buys 10mm and a surprise. **Raise `USABLE_MM` only against a slicer screenshot.** `/generate` rejects any other `size_mm` with a 400 and the UI is a `<select>`; `poster.py` itself still meshes any size, since the tests build 40mm posters. Pinned by `test_every_offered_size_fits_the_plate` and `test_generate_only_sells_the_three_offered_sizes`. `check_output.py`'s per-axis y rule is the backstop, and the `build_poster` over-plate guard now only fires on an explicit `chin_mm`/`frame_mm` override.

The text body is meshed on its **own** grid, `TEXT_SUB` (4) times finer than the frame's — 0.1mm at defaults. It sits on the flat ring, so it needs only a constant top array, not the frame heightmap, and that is what decouples the two grids. The mask is `(H-1)*TEXT_SUB+1 × (N-1)*TEXT_SUB+1`, **not** `H*TEXT_SUB × N*TEXT_SUB`: `heightmap_mesh` and `_slab_mesh` both map row → `(rows-1-row)*res`, and that `-1` is a vertex count that does not scale with `TEXT_SUB`. Sized naively the caption sat `(1 - 1/TEXT_SUB)*res_mm` = 0.3mm north of the frame on every row. Sized this way fine row `r*TEXT_SUB` **is** frame row `r`, exactly, in both axes and at every resolution — pinned by `test_the_text_grid_is_registered_to_the_frame_grid`, the only test that puts the two meshes side by side. On the terrain's 0.4mm grid an 8mm capital was ~20px tall with 0.4mm stair-steps and a 0.4mm dilation fattening every stroke; at 4× the edge pitch and the dilation both cost 0.1mm (250mm "HB-EZE": 2796 → 27304 verts, ink area 175.7 → 124.5mm²). 6× buys 0.6% more fidelity for 2.2× the vertices, so 4× it is.

**The caption is set bold and its strokes are floored.** A 0.4mm nozzle cannot hold a stroke under ~0.8mm (0.84 target, two 0.42 extrusions): at 1.5–2.2 extrusion widths a glyph is pure perimeter and Arachne flips between one and two beads along a single stem. `FONT_PATHS` therefore tries the box's **bold** faces first (`(path, face index)` pairs — Helvetica.ttc is a collection whose index 1 is Bold), and the first is **Trebuchet MS Bold**: Arial and Helvetica Bold set the g's ear, the t's hook and the i-dot under 0.2mm from their stems at 7mm caps, and any dilation welds them ("First Solo Flight" went from 3 holes to 6). Trebuchet has no "→", so `_line_mask` takes each character's face from `_glyph_font` — the first `FONT_PATHS` face whose glyph is not the .notdef box (compared against U+FFFF, a noncharacter; `getmask("")` is empty, not the box), i.e. Arial Bold for the arrow — and draws every glyph on the line's baseline (`anchor="ls"`), since the two faces' ascenders differ, and `_text_mask` then renders each caption line on its own and calls `_dilation_px`/`_dilate`: `_stroke_mm` measures the rendered stroke by successive erosion, and the line is dilated toward `MIN_STROKE_MM` (0.84mm, a *target*), on top of the 1 fine pixel the mesher's four-corner cell rule needs anyway. Per line, because line 2 is the smaller face and needs the most. The erosion stops at three quarters of the ink gone, not at an empty mask — eroding to empty measures the *fattest* feature on the line, which for "ZURICH → ALTENRHEIN" is the arrowhead (1.60mm against a 1.1mm stem) and would leave every stem unthickened. The target gives way to topology: `_dilation_px(render, res)` steps `n` down from what the stroke wants until `_topology` (4-connected ink blobs, holes via the Euler number with an 8-connected background — the only consistent pairing) of the dilated **tracked** render equals the raw render's, *and* every counter survives `MIN_COUNTER_MM` (0.4mm) more growth; it says so on stdout ("keeps") when it stops short. Tracked, so the letter gaps tracking pays for never veto. `n=1` is the mesher's minimum and is kept even if it fails (Trebuchet at 120mm loses one counter on line 2). The old quarter-cap-height cap is gone. Pinned by `test_the_caption_keeps_its_counters_and_dots`, which fails with Arial Bold first. **And the dilation is paid for in tracking.** Growing a glyph by `n` fine pixels on every side eats `n` off *each* side of every gap, so a line dilated by `n` and left at its designed advances closes any gap under `2n` — at `size_mm=170` the subtitle took `n=2` and `"HB-EZE · 02.08.2026"` came out as 7 blobs where it has 17 letters, which is the opposite of the readability the thickening exists for. `ImageDraw.text` has no tracking parameter, so `_line_mask` lays the line out itself: pen x accumulates `font.getlength(ch) + 2n` and each glyph is drawn on its own, giving back exactly what the dilation took. `n` is measured off a first, untracked render (it depends only on the rendered stroke); the tracking then widens the line, so the width fit is redone against the **tracked** ink or a long caption walks off the bar, and `n` is deliberately *not* re-measured after that shrink — tracking and dilation have to stay the same number, and a hair under `MIN_STROKE_MM` beats letters that touch. The price is kerning: per-character advances only, so a "VA" pair sits a shade loose, which is the direction this is pushing anyway. Pinned by `test_the_stroke_floor_does_not_merge_the_caption_letters`, which counts 4-connected ink blobs per line and requires at least one per ink-bearing character (`>=`, not `==`: an accented capital is legitimately two blobs).

Visual params (`frame_mm`, `relief_mm`, `frame_height_mm`, `text_mm`, `groove_w_mm`, `proud_mm`, `wall_mm`) default to `None` = auto: `poster.resolve(p)` scales them from their 250mm base by `size_mm` and floors them for printability, so an 80mm poster keeps the 250mm look. `build_poster` and `check_output.py` both resolve first; `/generate` returns the resolved dict for the preview. The floors are printability floors and one of them is about a part that is not the one named: **`groove_w_mm`'s floor is 1.44**, because what has to survive the printer is the *strip*, `groove_w_mm - 2*clearance_mm` wide. At the old 1.2 floor that was 0.60mm — 1.4 extrusions at a 0.42mm line width, so a 16mm-tall fin printed as one wobbly bead with no perimeter pair to brace it. 1.44 − 0.60 = **0.84 = exactly 2 × 0.42**, the pure-perimeter case `docs/print-settings.md` §5 tunes the path plate for.

## The wall is heart rate

Per order, in `build_poster`'s sequence: the legs of one sport form one wall (`group_walls`); each leg's stations carry its 30 s-smoothed heart rate (`leg_stations`); a wall's passes over the same road collapse onto one line at their average HR (`collapse_passes`); different sports sharing a road move into side-by-side lanes (`assign_lanes`); the walls are rasterised on a 4× grid where a crossing cuts the earlier wall and pieces under `MIN_PIECE_MM` drop (`wall_masks`); the groove is carved from those masks grown by the clearance (`groove_from_masks`); and `wall_tops` puts each wall's top at the terrain under it plus its heart-rate height. Two numbers from `_wall_dims` run through it: `r = lane_mm / res_mm` relief pixels is both "the same road" and the lane pitch, and every snap and lane move eases over `ramp = ceil(2r)` stations.

**The scale is fixed, and the low line is the floor.** `wall_height(hr, p)` = `proud_mm + clip((hr - 100)/100, 0, 1) * wall_mm`, mm above the ground under each station, on the fixed `HR_SCALE_BPM` (100, 200) for every customer; NaN (no HR, an open-water swim) prints the low line at `proud_mm`, the same as ≤100 bpm. The bpm is smoothed first: `activity.smooth_hr` is the centred `HR_WINDOW_S` (30 s) mean of the finite samples, so an optical spike or dropout does not print as a saw-tooth top, and the middle of an HR gap longer than the window stays NaN, the low line. `wall_mm` is a scaled visual param, 12.0 at 250mm, floor 3.0, rounded up to whole layers by `resolve()` (10.56 at 216, 5.76 at 120) — a starting value for the first test print. `leg_stations(leg, bounds, M)` projects a leg onto relief-plate pixels and resamples it with `_offsets` (~1 px apart), carrying `activity.smooth_hr` as a NaN-aware weighted interpolation (NaN where the gap holds over half the weight); `legs_bounds` is `track_bounds` over every leg, so the whole order shares one map. Walls are rasterised `WALL_SUB` (4) times finer than `res_mm`; `_wall_dims(p)` gives `(res_f, W_mm, dil_px, lane_mm)`: the fine pixel, the drawn strip width (core `groove_w_mm - 2*clearance_mm` plus `WALL_PAD_PX` = 3 fine pixels, see the raster walls below), the crossing cut's dilation (`clearance_mm` up to whole fine pixels) and the lane pitch `W_mm + (2*dil_px + 1)*res_f` — twice the cut's reach, so a lane chamfered round an outside corner (~0.92 of the pitch from the earlier wall) still clears a neighbour's cut.

**A road passed twice is one wall at the average heart rate** (spec 6.5). `collapse_passes(pieces, r_px, ramp)` takes one sport's station pieces in time order. A station is a *repeat* when an earlier station (raw position, repeats included) lies strictly within `r_px` and is in another piece or more than `3*r_px` stations back in its own — the index gap keeps a station's own neighbours and a tight hairpin from counting as a second pass. Repeats snap onto the polyline of the non-repeats (`_nearest_on_segments`; a canonical station with no canonical neighbour is a point segment), eased over `ramp` stations by `_ramp`, so a lap, an out-and-back or the same ride sent twice prints one wall on the first pass's line, never two offset by GPS drift. Each station's hr is then the mean of the *finite* hr of every station within `r_px` of its new position: a pass without HR does not dilute it, and a stretch no pass has HR on stays NaN, the low line. `r_px` is the tolerance for "the same road" in relief pixels, and `build_poster` passes one lane pitch (`lane_mm / res_mm`), so a repeat must come closer than one lane to an earlier station. Pairwise distances run in row chunks, O(n²), fine to ~20k stations per wall.

**Legs that share a road run in side-by-side lanes** (spec 6.6). `assign_lanes(walls, lane_px, r_px, ramp)` takes the collapsed walls earliest first and moves only the later ones: wall 0 never moves, hr is never touched. A station of wall `i` is in a lane where some earlier wall's **input** (pre-lane) polyline lies strictly within `r_px`, and its `ref` is the *earliest* of those walls. Its target for lane `k` is the foot on ref (`_nearest_on_segments`) plus `k * lane_px` along ref's left normal. That normal is not the segment's own `(-u_y, u_x)`. `_lane_ref(wall, ramp)` gives each ref vertex `v` the unit mean of the segment normals `v-ramp .. v+ramp-1`, clipped at its piece's ends. The station then takes the two vertex normals of its foot's segment, interpolated at the foot. A corner therefore turns the lane over ~`2*ramp` stations instead of jumping from one offset line to the next. The window is `ramp`, not the two adjacent segments: with two segments, a leg whose own track cuts the *inside* of a 90° corner while its lane runs *outside* has about one station along the lane's arc, and it chorded across at 0.745 of the pitch, inside a neighbour's cut. With `ramp` = 4 the four 90° cases with the track 0.4 px off (lane inside/outside × track inside/outside) measure 0.968 / 0.908 / 1.000 / 1.000 of the lane; that was measured at the test parameters only. The side follows ref's direction of travel, so a leg running the road the other way still lands in the same lane. Along each run of lane stations the normal is flipped only where it is over 150° from the previous station's (`n_i·n_{i-1} < LANE_FLIP_DOT` = −0.866). That catches a collapsed out-and-back ref, whose two passes lie on one line facing opposite ways and tie under `argmin`, and without it isolated stations landed a full `2*lane_px` across. It does not catch a corner. The old `< 0` threshold also fired at 120–135° corners, where the windowed normals of consecutive stations can be over 90° apart, and switched the lane side for the rest of the run. The sweep (90/120/135°, both turns, track 0.4 out to 2.0 px in, both parameter sets) never saw consecutive corner normals below −0.707. `k` is the smallest `k ≥ 1` whose target, pushed off ref the way the stations are below (`_push`), lies at least `LANE_CLEAR_FRAC * lane_px` (0.9 of the pitch) from every earlier wall's **output** polyline; ref's own unmoved road is lane 0, which the push keeps `k` lanes off, so only the stretches of ref that moved count against it and two walls alone always take lane 1, exactly as before. Lanes `1..i+1` are tried; where none clears (an earlier wall crossing the shared road) the station stays in lane 1 and the crossing cut decides (the `ponytail:` there). **0.9, not the whole pitch:** with the whole pitch, a neighbour about two lanes off with GPS jitter let lane 1 clear only where it sat at ≥ 2 lanes, so neighbouring stations flipped 1↔3, every flip drew a segment straight across the neighbour, and the crossing cut deleted it or cut it up (the final review's probes at 216: 44–56 flips and the neighbour gone whole; a triathlon swim beside a shared road in 4–7 pieces with 48–61% of it lost). 0.9 is safe because a neighbour is only cut where the centreline gap is under `W + sqrt(2)*dil*res_f` (the Chebyshev dilation reaches √2·dil fine pixels diagonally), and 0.9 of `W + (2*dil+1)*res_f` stays above that at every res and size (pinned in `test_wall_dims_keep_neighbouring_lanes_clear_of_the_crossing_cut`). **Then `k` is held and eased per lane run** (a maximal stretch of consecutive lane stations in one piece). The held lane is `k`'s max over the run's stations within ±`ramp`, so a lane goes up `ramp` stations before it is needed and comes down `ramp` after, and a neighbour jittering across the 0.9 line cannot make it alternate. The offset `o` is the held lane's mean over ±`ramp // 2`, clipped at the run's ends, so a real change from lane a to lane b, past a wall that genuinely blocks it, happens once each way as a linear move over ~`ramp` stations, never a jump. Where `k` is constant along a run `o == k` exactly (integer sums over integer counts), so every two-wall order and every earlier lane fixture is byte-identical to 3840a94. Pinned by `test_a_jittering_neighbour_two_lanes_off_never_flaps_the_lane` and `test_a_jittery_swim_beside_a_shared_road_is_not_cut` (3 seeds each: no lane change, no step over 1.5 lanes, the neighbour one piece with ≥ 99% of the area it has without the laned wall), `test_a_lane_change_that_is_really_needed_happens_once_up_and_once_down_eased` (a blocker 1.05 lanes off: lane 1, 2, 1 with exactly two changes, no sideways step of half a lane, ≥ 0.9 lane off the blocker, the blocker one piece) and `test_a_neighbour_jittering_across_the_clear_line_is_held_off_not_flapped` (a neighbour at 1.9 lanes ±0.5 px, which lane 1 clears at one station and not the next: without the hold and the ease it flipped 22–26 times and lost 57–72% of the neighbour). Counting the earlier walls' inputs instead, as the first version did, gave two later walls on either side of an earlier one, each within `r` of it but over `r` from each other, the same lane on the same target, and the crossing cut then deleted the earlier of them whole: pinned by `test_two_later_walls_either_side_of_an_earlier_one_take_two_lanes` at both parameter sets, which also asserts every wall keeps a piece after `wall_masks`. Three legs on one road still make lanes 0, 1, 2. The target, the foot plus `o * lane_px` along the normal, is eased in with `_ramp(in lane, piece, ramp)`. Then every lane station closer than `o * lane_px` to ref is pushed straight away from its nearest ref point to exactly that distance, with no side check, and this repeats until all are at `o * lane_px * (1 - 1e-6)` or more. After 64 rounds it prints one line, `path: lane push-out did not converge at N stations`, with no coordinates. A narrow inside corner converges at about cos(interior angle) per round. On the lane side of a straight road the push overrides the ramp (with `lane_px == r_px` every present station starts inside its lane), and it keeps a leg easing off the road from dipping back toward it. **The ceiling:** a lane is clear of a neighbour's crossing cut only where the shared road turns up to 90° and the later track stays within ~0.4 px of it. At a sharper corner, at a turnaround (a 180° corner), or where the later track cuts the corner, the lane can come inside the cut's reach. At a collapsed out-and-back's turnaround the later wall's last few stations can land across the out pass. Stations next to a narrow inside corner can be pushed across the other leg, because the push from one leg of a 45° wedge overshoots the other. Task 9's crossing rule then gives the *earlier* wall a short gap there. The upgrade is lanes built from a true offset polyline of the earlier wall's road, with round joins outside and trimmed loops inside (the `ponytail:` on `assign_lanes`). Repeated stations are dropped from a ref (collapse stacks several on one vertex), and a one-station piece is no ref. Pinned by `test_lanes_round_a_sharp_corner_stay_clear_of_the_earlier_wall` at 90° (every later segment, sampled at 10 points, at least 0.9 lane from the earlier wall, no step over 1.5 lanes). Past the ceiling, `test_a_sharp_corner_never_switches_the_lane_side_for_the_rest_of_the_run` pins only that the side after a 90/120/135° corner is the side before it. It skips stations whose foot is within 3 lanes of the corner and asserts no clearance. `test_an_out_and_back_earlier_wall_keeps_the_later_wall_on_one_side` asserts one side and the lane distance (wherever the lane is fully eased in) for a later track on the lane side, on the far side, and itself an out-and-back. On the lane side the last station lands across the out pass, so that case skips feet within 3 lanes of the turnaround, the same way. The other two hold at every station, so a target clip that stops short of the out pass cannot come back unnoticed: one did, and it put 4–12 stations on the wrong side in those two cases.

**The walls are rasters on a 4× grid, and the groove is built from them** (spec 6.5, 6.6, 6.9). Every wall is a bool vertex mask on `((M-1)*WALL_SUB+1)²`, the caption's registration: fine vertex `r*WALL_SUB` is relief vertex `r`. `_ribbon` draws each piece as one rectangle per segment, `W_mm` wide along that segment's own normal (an averaged station normal pinches a kink to cos(turn/2) of the width), plus a bevel at every vertex: the rectangle spanned by both segments' normals there. Without the bevel the wedge two rectangles leave outside their shared vertex caught pixel centres even at a 1° turn, and a curved wall had a pinhole every few mm. Zero-length segments are skipped. `wall_masks(walls, M, p)` cuts crossings last wall first: the later wall runs through, and each earlier one loses everything within `dil_px` (Chebyshev, so at least `clearance_mm` of real gap) of what is left of every later wall. Then each 4-connected piece (`_components`, a pure-Python floodfill like `_sea_mask`, yielding one full-size mask at a time) shorter than `MIN_PIECE_MM` = 3.0 (area / `W_mm`) is dropped, whether a crossing cut it off, the plate edge clipped it or it is a short wall or GPS stub on its own, with the one-line `path: dropped a 1.3mm wall fragment, under the 3mm minimum` (a length, never a coordinate). A dropped fragment cuts nothing. **Ceiling:** the cut follows the through wall's grown outline, so an oblique crossing leaves a pointed tip that meshes under 0.84mm over its last ~0.5–1.1mm (20° at res 0.4: ~1.1mm at 0.60mm), and a square wall end tapers the same way (the `ponytail:` at the cut; square the cut across the earlier wall if tips break off). A leg crossing itself is one mask and is never cut, and Task 8's corner ceiling shows up here as a short gap in the *earlier* wall. `groove_from_masks` grows every wall by `dil_px`, carves each relief cell whose closed fine block holds any grown vertex, and returns those cells' vertices, so every carved cell is floor-flat and the floor opening contains every strip plus its clearance by construction. `wall_tops` gives each station `_snap(surface at its nearest relief vertex + wall_height)` and paints each segment's ribbon with the **higher** of its two ends, which is on the grid and never under `proud_mm`. The mean was not: two ends an odd number of layers apart average to half a layer off the grid, exactly on Orca's mid-layer slicing plane, and on a 100→200 bpm ray that was 93% of the wall's top (pinned by the layer-grid test's ramp case). Segment ids go into an `"I"` image and are looked up in float64, since an `"F"` image is float32 and reads 10.04 as 10.0400000572. `wall_mesh` is `_slab_mesh` over the mask's fine cells from `SLOT_FLOOR_MM` up to that top. **`WALL_PAD_PX` is 3, not 2:** Pillow truncates polygon vertices, and the four-corner cell rule then shaves up to ~2.7 px off a drawn width between the axes. With 2 pixels a 0.84mm core meshed 0.75mm at 30° and res 0.5 (0.815 at 0.4). With 3 the strip holds at least 0.85 mid-wall at any heading and sub-pixel phase (worst 0.850 at res 0.5 and 0.25, 0.860 at 0.4, swept at 1° steps). `_min_width_mm` (test helper) reads the perpendicular run inside the meshed *cells* in 0.05 px steps, because rounding each sample to its nearest vertex (the flight tool's old groove test) reads up to a pixel wide and passed the 0.75mm wall. At 216 a 1200mm serpentine wall crossed by a second wall takes 0.6 s to mask, 0.3 s to groove and 0.5 s to mesh (375k vertices).
