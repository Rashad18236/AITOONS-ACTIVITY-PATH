# Flight Path Poster

Local web tool that turns a FlightRadar24 track export (KML/CSV) into three ready-to-print OrcaSlicer projects:
`frame.3mf` (black backplate + ring, white text as its own body), `relief.3mf` (multi-body
green terrain / blue water (lakes, rivers, sea) / grey high-alpine band, runways and main roads (same slot 3), one AMS slot per colour) and `path.3mf` (the flight-path strip:
a red wall following the flight altitude, standing in a constant-floor slot). Every print setting is embedded: open, slice, print.

## Rules

- Printed in PLA on a Bambu Lab A1 with a 0.4 nozzle (the only printer the projects target), 256×256mm plate, poster is one piece
- Three sizes only, `poster.SIZES_MM` = (216, 170, 120), 216 the default
- Footprints are checked against `USABLE_MM` (226), never the bare 256 plate
- Design decisions with Fable, implementation via Opus subagents
- Ponytail full mode during coding: laziest working solution, heightmap ops over 3D booleans, no speculative features
- Local only (localhost), single user, no auth, no persistence of user data; OSM/runway responses are cached in process only

## Run

```bash
uv run uvicorn app:app --reload
# open http://localhost:8000
```

## Architecture

- `app.py` — FastAPI: upload/generate routes, serves `static/`
- `poster.py` — core: parse track → snap takeoff/landing ends to the nearest OurAirports runway (`snap_runways`, live CSV, lru_cached in memory) → fetch DEM (AWS Terrain Tiles, terrarium, no key) + OSM water, coastline, runway and road geometry (one Overpass call, `_overpass` lru-cached per query, mirrors tried until one answers *without* a `remark`) → compose 2D heightmaps (frame + text mask, green/water/snow relief, slot) → mesh to `frame.3mf` + `relief.3mf` + `path.3mf` (OrcaSlicer projects, `write_3mf`)
- `orca_profile.py` → `orca_a1_pla.json` — the A1 0.4 / 0.24 Draft / Bambu PLA Basic system profiles, inherits chains flattened, vendored (committed). Regenerate with `uv run python orca_profile.py` against the installed Orca after an Orca update
- `static/index.html` — upload form, parameter sliders, three.js preview, downloads
- `test_poster.py` — self-check: parse sample track, build small mesh, assert watertight + strip fits slot

**Every output is a finished OrcaSlicer 2.3.2 project, A1 0.4 only.** Orca fills a loaded project's config from compiled defaults and applies it as "(modified)" edits over the preset `print_settings_id` names, so a partial `project_settings.config` would blank `machine_start_gcode` and every key it left out. `write_3mf` therefore embeds the whole vendored chain from `orca_a1_pla.json` (filament lists tiled per slot, machine/process lists left at length 1) and puts `COMMON`, `PLATES[plate]` and the per-part `PART_OVERRIDES` (the caption: 3 walls at 0.40) on top. Those tables in `poster.py` are the truth and `docs/print-settings.md` is the rationale. The filament slots are fixed per plate (`SLOTS`): relief.3mf always declares three filaments, even when a dry poster uses only slot 1, so the AMS mapping never shifts. Placement is on the build item only, never in the vertices (`check_output.py` and `read_3mf` measure the local frame): x centred on the 256 bed, y centred in the space behind the prime tower (`138 - h/2`, i.e. the 216 two-line frame sits at y 25–251, brim 20–256), and z dropped onto the bed (the strip's own floor is 1.16). The tower is 130mm wide at x 63 / y 5, its brim 0–16. Sliced at 0.24 on the 216 order it is 6.75mm deep on the frame. That is Orca's height-based stability minimum: at 0.12 a 180mm tower sliced the same depth. With brim and cone it reaches y 16.8, 3.6mm short of the frame's brim; on the relief it reaches 17.3, against a brim at 36. `USABLE_MM` is unchanged. `test_orca_slices_every_plate` runs the real Orca CLI headless when it is installed.

Key invariant: every body comes off the same heightmap, so they always fit. The relief plate glues into the frame ring (fit clearance ceil-rounded up to a whole pixel, ≥0.2mm per side — rounding down gives an interference fit); the strip glues into the slot with 0.30mm per side. The slot is carved to a constant `SLOT_FLOOR_MM = 1.16` floor (depth varies with terrain, the floor does not), and the strip runs from that floor up to the flight altitude on the terrain's own vertical scale, clamped to at least `proud_mm` above the terrain under each station.

**Caps follow the slot.** Water and road caps are not kept off the groove: inside it `cap_top` drops to `SLOT_FLOOR_MM` and `cap_bot` to `SLOT_FLOOR_MM - SLOT_CAP_MM`, so the slot's walls and floor are blue over water and grey on a road. Kept off (and meshed per four-corner cell), 0.3mm of clearance plus up to 0.4mm of full-height green rim showed on each side of the strip along the whole path, even over the sea. The strip still seats on the flat `SLOT_FLOOR_MM`, now on the cap's top. `SLOT_CAP_MM` is 0.48 (2 layers), not `cap_mm`, because 1.16 − 0.96 would leave only the 0.2mm first layer green; the green under it sits at 0.68 = 0.2 + 2×0.24, on the grid. (That is also why the floor is 1.16 and not 0.92, the boundary nearer the old 1.0: 0.92 − 0.48 leaves 0.44mm.) Green is carved only under cells the mesher really meshes, so a 4px road leaves no orphan pits along its edge.

The DEM is blurred once (`smooth_px` = 1px) and the terrain surface is snapped to a printable layer boundary before caps and slot are cut, so flat ground slices as uniform layers. The grid is `FIRST_LAYER_MM + n*layer_mm` (0.2 + n*0.24), *not* `n*layer_mm` — the printer's first layer is thicker than the rest. The layer is 0.24 since the 216 order was measured with the Orca 2.3.2 CLI. At 0.12 the relief took 18.84h with 155 filament changes (one per layer, because the roads drape into the slot) and the frame 8.29h (ironing alone ~60%). At 0.24, with frame ironing off and 7% infill and relief walls 2 / top 3 / 10%, the measured times are frame 2.69h, relief 9.55h with 77 changes and path 0.86h (`docs/print-settings.md` head has the variants). The terrain step is 7.6m instead of 3.8m, which the user accepted. One helper, `_snap(z, p)`, does it for the terrain, the strip top and the `z_snow` plane. Every fixed z is a layer boundary or a whole layer count, pinned by `test_fixed_constants_sit_on_the_default_layer_grid`: `SLOT_FLOOR_MM` 1.16, water `cap_mm` 0.96, text 1.20, `base_mm` 4.04, `plate_mm` 2.12, `frame_height_mm` 10.08 at 250mm (9.96 rounded up), `proud_mm` 0.96 at 250mm. The *scaled* thicknesses are not whole layer counts by luck, so `resolve()` snaps them: `_layers(v, p)` is `_snap`'s delta form and rounds `frame_height_mm`, `proud_mm` and `relief_mm` (the last through `exaggeration`, which is what reaches the relief ceiling) **up** to whole layers — up, because each has a printability floor that rounding down can cross. Without it a 170mm poster put the ring top at 10.81mm, 0.05mm above boundary 88 of the old 0.12 grid, and the slicer's rounding — not the geometry — decided which layer the black/white colour boundary landed on. `frame_mm`, `text_mm`, `groove_w_mm` and `chin_mm` are in-plane and are deliberately never snapped.

**The vertical scale is the terrain or the flight, clipped.** `to_mm` maps `span = max(e1 - e0, clip(max_alt - e0, *FLIGHT_SPAN_M))` metres onto `relief_mm * exaggeration`, `FLIGHT_SPAN_M = (300, 1000)`. Terrain range alone stretched Blackpool's 30m of coast over the whole relief (0.86mm/m): flat land read as hills and the 335m circuit hit the strip ceiling as a flat fence. Flight-aware it is 336m → 0.077mm/m, terrain ~1.7mm, the wall a rising 27.9mm profile. The clip keeps an airliner from flattening everything (1000m) and a low hop from exaggerating the ground (300m). In the mountains the terrain range wins and nothing changes (a 191–3820m Alpine flight keeps its 3630m span); a lowland flight with a high flight over it (Zurich test track, 340–706m terrain, 1500m flight) does get flatter — 366m → 1000m span. Blackpool land measures 0.6–1.7mm above the sea and the DSM residual is 0.005mm, so the relief is left alone.

**The sea is a coastline, not a polygon.** OSM has no sea polygons, only `natural=coastline` ways with land on their left. `_sea_mask` draws them as 1px 8-connected lines, labels the pieces with 4-connected floodfills and lets every segment vote +1 for the piece on its right, −1 for its left — votes, because a pier doubles back within a pixel and a single seed lands across it (99.8% of Blackpool flooded vs 48.5% by vote). Not the DEM sign: a polder is below zero and still land. `build_poster` sets the DEM to 0 under the sea *before* the one blur (terrarium carries bathymetry, −7.85m off Blackpool), so the shore blends with 0 and the sea prints as the usual flat conformal water cap. Closed coastline ways are islands and never reach the polygon rasteriser, which would paint them as lakes.

**Overpass answers 200 with partial data.** A query that hits `[timeout:120]` or `[maxsize:]` does not fail: it returns HTTP 200, the elements gathered so far, and a `remark` ("runtime error: Query timed out…"). The union is evaluated in order, so roads vanish first and the coastline next — and a missing coastline leaves the seabed bathymetry in the DEM. That showed up as a different street grid and "different relief" between two regenerations of one order, with mirror load flipping by the minute. `_overpass` therefore rejects any response carrying a `remark` (or no `elements`), tries the four `OVERPASS_URLS` in order, 150s each, one try per mirror (`_get(..., tries=1)`; tiles keep their retry), caches complete responses in memory per query string for the server's life (a raise is not cached, so a failure retries next call), and raises `RuntimeError` when all four fail. `build_poster` no longer soft-fails it: `/generate` is a 502 whose message reaches the status line, never a poster without its water. The >4° transoceanic guard still returns empty masks without asking.

**Grey is also runways and main roads, picked by zoom.** `fetch_osm_masks` works out the poster's ground scale in m per printed mm and asks Overpass only for the `ROAD_TIERS` classes whose limit it is under (tertiary ≤60, secondary ≤150, primary ≤400, trunk ≤1200, motorway ≤3000 m/mm): Blackpool at 36.7 m/mm gets tertiary and up, ≈8.5% of the plate plus 0.3% runway; residential would add another 15% and read as a grey block. Roads are drawn `ROAD_MM` = 1.2mm wide (3 extrusions, clear of the 0.84 colour floor); a runway at its OSM `width` (or `RUNWAY_M` = 45m) on the poster's scale, floored at `ROAD_MM`, and an `area=yes` runway as a polygon. If the drawn grey still exceeds `ROAD_MAX_FRAC` (15%) the finest class is dropped and it says so. Tunnels are skipped; no taxiways, aprons or `_link` roads. Roads print as the same draped cap as water, in the grey band's colour and slot 3 (no new spool); `lc` sets them after water, so a bridge is grey across the river, and never over snow.

**Grey is an elevation band, not a cap.** The terrain solid is split at the horizontal plane `z_snow` (= `snow_line_m` on the relief's own mm scale, snapped): green below, a grey solid from that flat plane up to the surface above. A conformal 0.6mm grey cap surfaced as a 0.26mm stripe on median alpine slope — under one extrusion width, which the slicer merges into the neighbouring colour ("blotted grey"). The two bodies meet exactly at `z_snow` and their union is still the same surface heightmap, so this changes colour volume, not shape. The footprint is the bare `elev >= snow_line_m` threshold intersected with `surface > z_snow` — no morphology: an opening dropped small peaks from grey while leaving them in green, so green towered above the plane and the two colours shared layers. A small peak is a solid band volume that prints fine, and cell-based meshing already drops sub-2-cell blobs. Water stays a conformal `cap_mm` cap — lakes are flat.

**The caption bar is a chin, and the text has its own grid.** `size_mm` is the poster's **width** and the square relief area; `chin_mm` is extra frame hung *below* it, so the frame grid is `(N + chin_px, N)` while `N`, `M` and `fpx` keep their formulas — the ring opening and the relief are unchanged by construction (byte-identical, and pinned by a test). A poster therefore measures `size_mm` × `size_mm + chin_mm`, and **both** must fit the 256 plate; `check_output.py`'s footprint rule is per axis for that reason. `chin_mm` is auto: it is whatever `text`/`text2` need beyond the ring's own bottom bar, `block + 2*TEXT_MARGIN_MM - gridded_ring` rounded up to a pixel, so no caption means no chin and every earlier poster is unchanged. `gridded_ring` is `(int(frame_mm/res_mm) - 1) * res_mm` — the bar *as the mesher lays it out*, since frame rows `N-fpx..H-1` span one pixel less than the nominal `frame_mm + chin_mm`. Line 2 is a subtitle at `SUB_RATIO` (0.65) of line 1 with `GAP_RATIO` (0.35) between them. Note the auto chin fires for **any** caption: a single-line poster at 250mm is 2.4mm taller than the bare square (252.4 vs 250), and a two-line one 10.4mm taller — which puts 250mm two-line **over** the 256 plate. That is why the largest offered size is **216**: `SIZES_MM = (216, 170, 120)` is the shop's list, and every entry has to (a) fit **`USABLE_MM`** with *every* caption it can be ordered with (216 two-line = 215.6 × 226.0mm, landing exactly on it) and (b) be a whole number of `res_mm` pixels. (b) is why it is not 245 or 218: `_grid` truncates `N = int(size_mm/res_mm)`, so 245mm is 612.5px and prints **244.4mm** — 0.6mm under nominal, which `check_output.py`'s ±0.5 footprint rule fails. On the grid the width is short by exactly one pixel, which that rule allows.

**A mesh that fits the plate does not fit the print.** `PLATE_MM` (256) is the physical bed and is *not* the ceiling anything is checked against. `USABLE_MM` = `PLATE_MM - 2*BRIM_MM - TOWER_GAP_MM - TOWER_MM` = **226** is, on both axes, and it is what the `build_poster` guard, `max_size_mm`, `check_output.py` rule 3 and `/dimensions`'s `fits` all use. Shipped once without it: a 240mm poster meshes 239.6 × 250.4mm, passes a 256 rule, and Studio refuses it — the 5mm brim `docs/print-settings.md` makes mandatory on a plate this size puts it 4.4mm off the bed on its own, and the 130 × 6mm prime tower still has to go somewhere. The tower is not optional for `relief.3mf`: its bodies overlap in z (216 D-EMFE order: terrain 0–18.44, water 0.68–3.80, roads 0.68–16.04, strip 1.16–28.04), so most layers carry two colours. `frame.3mf` is the exception — frame 0–12.68, text 12.68–13.88, no overlap, so it is a *single* filament change and could be printed without a tower; the budget deliberately does not exploit that, since one number that holds for every plate beats two that need remembering. Both axes get the tower allowance because the tower is a fixed-orientation rectangle: assuming it can be rotated into a side strip buys 10mm and a surprise. **Raise `USABLE_MM` only against a slicer screenshot.** `/generate` rejects any other `size_mm` with a 400 and the UI is a `<select>`; `poster.py` itself still meshes any size, since the tests build 40mm posters. Pinned by `test_every_offered_size_fits_the_plate` and `test_generate_only_sells_the_three_offered_sizes`. `check_output.py`'s per-axis y rule is the backstop, and the `build_poster` over-plate guard now only fires on an explicit `chin_mm`/`frame_mm` override.

The text body is meshed on its **own** grid, `TEXT_SUB` (4) times finer than the frame's — 0.1mm at defaults. It sits on the flat ring, so it needs only a constant top array, not the frame heightmap, and that is what decouples the two grids. The mask is `(H-1)*TEXT_SUB+1 × (N-1)*TEXT_SUB+1`, **not** `H*TEXT_SUB × N*TEXT_SUB`: `heightmap_mesh` and `_slab_mesh` both map row → `(rows-1-row)*res`, and that `-1` is a vertex count that does not scale with `TEXT_SUB`. Sized naively the caption sat `(1 - 1/TEXT_SUB)*res_mm` = 0.3mm north of the frame on every row. Sized this way fine row `r*TEXT_SUB` **is** frame row `r`, exactly, in both axes and at every resolution — pinned by `test_the_text_grid_is_registered_to_the_frame_grid`, the only test that puts the two meshes side by side. On the terrain's 0.4mm grid an 8mm capital was ~20px tall with 0.4mm stair-steps and a 0.4mm dilation fattening every stroke; at 4× the edge pitch and the dilation both cost 0.1mm (250mm "HB-EZE": 2796 → 27304 verts, ink area 175.7 → 124.5mm²). 6× buys 0.6% more fidelity for 2.2× the vertices, so 4× it is.

**The caption is set bold and its strokes are floored.** A 0.4mm nozzle cannot hold a stroke under ~0.8mm (0.84 target, two 0.42 extrusions): at 1.5–2.2 extrusion widths a glyph is pure perimeter and Arachne flips between one and two beads along a single stem. `FONT_PATHS` therefore tries the box's **bold** faces first (`(path, face index)` pairs — Helvetica.ttc is a collection whose index 1 is Bold), and the first is **Trebuchet MS Bold**: Arial and Helvetica Bold set the g's ear, the t's hook and the i-dot under 0.2mm from their stems at 7mm caps, and any dilation welds them ("First Solo Flight" went from 3 holes to 6). Trebuchet has no "→", so `_line_mask` takes each character's face from `_glyph_font` — the first `FONT_PATHS` face whose glyph is not the .notdef box (compared against U+FFFF, a noncharacter; `getmask("")` is empty, not the box), i.e. Arial Bold for the arrow — and draws every glyph on the line's baseline (`anchor="ls"`), since the two faces' ascenders differ, and `_text_mask` then renders each caption line on its own and calls `_dilation_px`/`_dilate`: `_stroke_mm` measures the rendered stroke by successive erosion, and the line is dilated toward `MIN_STROKE_MM` (0.84mm, a *target*), on top of the 1 fine pixel the mesher's four-corner cell rule needs anyway. Per line, because line 2 is the smaller face and needs the most. The erosion stops at three quarters of the ink gone, not at an empty mask — eroding to empty measures the *fattest* feature on the line, which for "ZURICH → ALTENRHEIN" is the arrowhead (1.60mm against a 1.1mm stem) and would leave every stem unthickened. The target gives way to topology: `_dilation_px(render, res)` steps `n` down from what the stroke wants until `_topology` (4-connected ink blobs, holes via the Euler number with an 8-connected background — the only consistent pairing) of the dilated **tracked** render equals the raw render's, *and* every counter survives `MIN_COUNTER_MM` (0.4mm) more growth; it says so on stdout ("keeps") when it stops short. Tracked, so the letter gaps tracking pays for never veto. `n=1` is the mesher's minimum and is kept even if it fails (Trebuchet at 120mm loses one counter on line 2). The old quarter-cap-height cap is gone. Pinned by `test_the_caption_keeps_its_counters_and_dots`, which fails with Arial Bold first. **And the dilation is paid for in tracking.** Growing a glyph by `n` fine pixels on every side eats `n` off *each* side of every gap, so a line dilated by `n` and left at its designed advances closes any gap under `2n` — at `size_mm=170` the subtitle took `n=2` and `"HB-EZE · 02.08.2026"` came out as 7 blobs where it has 17 letters, which is the opposite of the readability the thickening exists for. `ImageDraw.text` has no tracking parameter, so `_line_mask` lays the line out itself: pen x accumulates `font.getlength(ch) + 2n` and each glyph is drawn on its own, giving back exactly what the dilation took. `n` is measured off a first, untracked render (it depends only on the rendered stroke); the tracking then widens the line, so the width fit is redone against the **tracked** ink or a long caption walks off the bar, and `n` is deliberately *not* re-measured after that shrink — tracking and dilation have to stay the same number, and a hair under `MIN_STROKE_MM` beats letters that touch. The price is kerning: per-character advances only, so a "VA" pair sits a shade loose, which is the direction this is pushing anyway. Pinned by `test_the_stroke_floor_does_not_merge_the_caption_letters`, which counts 4-connected ink blobs per line and requires at least one per ink-bearing character (`>=`, not `==`: an accented capital is legitimately two blobs).

Visual params (`frame_mm`, `relief_mm`, `frame_height_mm`, `text_mm`, `groove_w_mm`, `proud_mm`) default to `None` = auto: `poster.resolve(p)` scales them from their 250mm base by `size_mm` and floors them for printability, so an 80mm poster keeps the 250mm look. `build_poster` and `check_output.py` both resolve first; `/generate` returns the resolved dict for the preview. The floors are printability floors and one of them is about a part that is not the one named: **`groove_w_mm`'s floor is 1.44**, because what has to survive the printer is the *strip*, `groove_w_mm - 2*clearance_mm` wide. At the old 1.2 floor that was 0.60mm — 1.4 extrusions at a 0.42mm line width, so a 16mm-tall fin printed as one wobbly bead with no perimeter pair to brace it. 1.44 − 0.60 = **0.84 = exactly 2 × 0.42**, the pure-perimeter case `docs/print-settings.md` §5 tunes the path plate for.

**Runway snap.** FR24 tracks GA aircraft badly near the ground, so a track's first and last fixes jump into the fields beside the airport and the strip ends in a hook. `snap_runways` cuts those ends and replaces each with a straight roll on the real runway from OurAirports' `runways.csv` (fetched on demand, `lru_cache`d in memory, never on disk; a failed fetch is non-fatal like water and the note says "runway data unavailable"). A fix is *aligned* with a runway direction when it is within 120m of the centreline and inside the window — approach only (up to 4km before the threshold) for landing, so on-runway and taxi fixes are cut and the rollout never doubles back; from 25% down the runway to 4km past its end for takeoff. Walking in from each end, the first 3 aligned fixes in a row end the clean part; no such run → that direction is not a candidate. A direction's score is the length of the aligned run that ends the clean part (the run the inward walk stops at, extended inward), **not** its total aligned count — on G-CEFM the bogus alt-0 tail in the field is itself a 3-run on 13's extended centreline and two downwind fixes cross that line by chance, so counts were 7 vs 5 where runs are 6 vs 3. The best run must beat the runner-up by `SNAP_MARGIN` (2) or the end is reported *ambiguous* and left alone. `takeoff_rwy` / `landing_rwy` (`EGNH 10`, case-insensitive) force one direction: same gate, falling back to a run of 1 because the forced case exists for climb-outs that turn before three fixes align; an unknown ident, a forced runway with no aligned fix, or missing runway data with a force set is a 400, never a silent auto. The note marks forced ends `(forced)`. Each end only searches its **own half** of the track: a circuit's climb-out lies on the reciprocal runway's approach line and, with more fixes than the real approach, otherwise won and cut the whole flight. Altitude is never used (FR24 pressure altitude is 100ft steps, QNH-shifted). The two new points per end (threshold, then 25% down the runway for takeoff / 55% for the rollout) sit at field elevation, which can be under the DEM terrain — the strip's `proud_mm` clamp lifts them. It runs in `app.py` between `parse_track` and `build_poster`, not inside `build_poster`, so the "Runways: takeoff EGNH 10, landing EGNH 10" note reaches the status line and every `build_poster` caller is untouched; `Params.snap_runways` (default on) turns it off. The gates are fitted to one G-CEFM flight at Blackpool (EGNH).
